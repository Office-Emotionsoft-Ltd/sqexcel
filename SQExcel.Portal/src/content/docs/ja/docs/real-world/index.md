SQExcel は、小規模なアプリ開発から100テーブルを超える大規模システムの保守運用まで、幅広い現場で使えます。ここでは開発規模別に3つのシナリオを取り上げ、それぞれで SQExcel がどう役立つかを具体例で紹介します。

## 3つのシナリオ

| シナリオ | 想定規模 | 主な使いどころ |
|---|---|---|
| [小規模開発で使う](/ja/docs/real-world/small-scale/) | アプリDB1・接続2・テーブルグループ1・テーブル20個・開発者1〜2名 | 初期データ・テストデータの投入、本番への初期データ展開 |
| [中規模以上の開発で使う](/ja/docs/real-world/medium-scale/) | アプリDB2・接続4・テーブルグループ3・テーブル50個・開発者3〜10名 | テーブルグループによる整理、環境間のテーブル定義差異への対応 |
| [大規模システムのメンテナンスで使う](/ja/docs/real-world/large-scale/) | アプリDB3・接続4・テーブルグループ3・テーブル100個以上・保守要員3〜5名 | メンテナンス対象の絞り込み、大量データからの抜き出し・一括修正 |

---

## 各シナリオで使うデータについて

:::note
3つのシナリオはそれぞれ異なるデータベースを使いますが、いずれも[サンプルDB](/ja/docs/sample-db/)で紹介したネット広告代理店の販売管理システムをモデルにしています。シナリオごとにテーブル数やデータ量は異なりますが、扱うテーブルは[サンプルDB](/ja/docs/sample-db/)で定義したものに限定しています。

SQL Server・Oracle・PostgreSQL はスキーマ単位でテーブルを管理するため、画面や入力シート上のテーブル名は `[スキーマ名].[テーブル名]` の形式で表示されます。スキーマは次の4種類です。

- **accounting** - 会計系
- **applog** - ログファイル
- **hr** - 人事系
- **sales** - 販売管理システム系

各スキーマの配下には、そのカテゴリーに属するテーブルが配置されます。
:::
